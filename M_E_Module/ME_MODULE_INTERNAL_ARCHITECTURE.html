M&E Module — how it works, end to end

The build blueprint for the Donor Report Writer. Shows how three entry paths converge on one shared core; how the Impact Pro tier carries both proposal credits (pre-award) and M&E reports (post-award); how the isolated, killable agent module runs; and where every piece comes from. Built for Cursor/Claude Code context, not for users.

Pattern · modular monolith, one seam Runtime · Claude Agent SDK on Railway worker Autonomy · Level 2 + 3 human gates Tier · Impact Pro $99 (dual-capability)
EXISTING — reuse/extend core REUSE — external OSS/service BUILD — our IP (the moat) agent (autonomous) human gate (server-enforced)
01

Three ways in — all converge on one core

Path A · the original funnel
Via NGOInfo.org
Discovers a funding opportunity on the WordPress site → signs up → writes a proposal. The pre-award journey we already have.
Path B · direct to product
Direct to GrantPilot
Comes straight to the app for proposals, never touching the WordPress site. Already supported today.
Path C · the new M&E door
"Won a grant anywhere"
Arrives in reporting-deadline pain — won a grant with us or anyone else. Needs a report now, not a proposal. The new top-of-funnel.

The key design fact: Path C does not require ever having used NGOInfo or written a proposal. A charity can enter purely for M&E. But because they pay for Impact Pro, they also receive proposal credits — so the moment they need to bid again, the pre-award product is already theirs. One tier, both needs, served seamlessly.

02

Impact Pro — one tier, two capabilities

Impact Pro $99 / mo
Everything in Impact, plus M&E reporting. A single subscription that serves whatever the NGO needs next — winning the next grant or reporting on the last one. Entitlements gate both capabilities from the same plan claim in the JWT.
PRE-AWARD Proposal credits
Fit scans + proposal generation (inherited from Impact). Already built — the M&E tier simply carries the same entitlements.
POST-AWARD 2 M&E reports / month
The new donor-report writer. Quota enforced like proposal regeneration. The reason a Path-C user subscribes.

08

Isolation & the three kill switches

🛑 Plug it out without touching GrantPilot

The module fits naturally but stays separable. If it delays launch, runs hot, or misbehaves — any one of these severs it, and the proposal product keeps running.
SWITCH 1 · CODE
Un-mount + flag off
Remove the single router-include and turn the UI feature flag off. The M&E API and screens vanish; core untouched.
SWITCH 2 · RUNTIME
Worker → 0
Scale the background worker to zero. The agent pipeline stops; the main API serving proposals never notices.
SWITCH 3 · DATA
Drop 4 tables
Because FKs point inward only and no core migration touches M&E, dropping the 4 tables leaves the core schema intact.

Why this matters for the build: the dual-capability tier means a paying NGO is never stuck — proposals and reports are both there. The isolation means you are never stuck — if M&E threatens the launch or the running product, it unplugs in three independent ways. Fits naturally; kills cleanly.
