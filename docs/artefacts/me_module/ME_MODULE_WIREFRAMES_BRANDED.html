Stage 04 → Gate 1 · Human

The knowledge bank, confirmed

The reconciler agent merges every extraction into one picture and — crucially — surfaces contradictions instead of silently averaging them. The human resolves each. This confirmed knowledge bank becomes the only thing the writer is allowed to use.

The pipeline cannot advance past this gate without recorded confirmations — enforced server-side.

Funder-aware, not blank-page

Stage 06 → Gate 3 · Human

The fact-safety net

Synthesis agents write each section (reusing the humaniser rules — challenges and adaptation included, not a glossy everything-was-perfect story). Then the fact-safety critic checks every specific claim back against the sources and flags mismatches. The human stays the author — accepting, editing, overriding.

This is the guardrail that makes a compliance product trustworthy.

Stage 08 · Export

One input → the funder's format

docxtpl renders the confirmed content into a hand-designed funder layout — RAG ratings, indicator tables, the lot. Re-export is idempotent from stored content; "duplicate for next period" turns the saved knowledge bank into recurring revenue.

How to read this blueprint

  • Purple stages run themselves. Classification, extraction and reconciliation happen in the background job queue — the user can close the tab and the work continues.
  • Blue gates are the product's conscience. Three points where the pipeline halts for a human: confirm the facts, fill the gaps, approve the draft. Each is enforced on the server, not just the screen.
  • The critic is the difference between a compliance tool people trust and a liability. Every number in the final report traces back to a source document or a human answer.
  • The build reuses the plumbing (Docling, Claude Agent SDK, docxtpl, n8n) and builds only the brain — orchestrator, reconciler, gap/compliance agent, critic, funder templates — the part with no open-source equivalent and all of the moat.
